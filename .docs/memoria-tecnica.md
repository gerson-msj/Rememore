# Memória técnica reutilizável — Stack .NET

**Situação:** fundação visual inicial implementada na Spec 01. CMP-001 está revisado e CMP-002 foi validado pelo operador no `/lab`; integração em páginas permanece para uma unidade própria. CMP-003 foi concluído e validado pelo operador no `/lab`; não foi integrado a páginas e sua integração requer unidade própria.

## Estrutura da solução

- `Rememore.slnx` contém `src/Rememore.Client` (Blazor WebAssembly standalone, .NET 10) e `src/Rememore.Api` (ASP.NET Core Minimal API, .NET 10).
- O cliente registra `HttpClient` com `ApiBaseUrl` e `EstadoTema`. O tema global é inicializado antes da liberação do roteador. `/` redireciona temporariamente para `/lab`; a página inicial está em `/inicio`.
- A API experimental expõe `GET /api/categorias`, usando `Turso.Data.Sqlite.Provider` 0.8.2 via ADO.NET. Criação e seed de Categorias na inicialização são experimentais, não uma política de produção.
- Publicação: `.github/workflows/publish-pages.yml` para GitHub Pages e `Dockerfile` para API na Render. A configuração ainda aponta para `Stack2`; `develop` é a branch de trabalho e `main` será publicação após transição deliberada.
- `Stack1/` é implementação histórica protegida para consulta pontual. Não reutilizar automaticamente sua arquitetura, CSS ou dados.

## Recursos visuais

- `src/Rememore.Client/wwwroot/css/bulma.min.css`: Bulma 1.0.4, carregado globalmente pelo `index.html`.
- `wwwroot/css/paletas.css` contém as paletas clara e escura iniciais e tokens Bulma. `app.css` mantém aliases semânticos `--cor-*` usados pelos estilos do cliente.
- Font Awesome Free 7.3.1 e fontes locais estão em `wwwroot/css/` e `wwwroot/webfonts/`. `wwwroot/css/fontes.css` registra as famílias Chewy, Damion, Dekko, Dongle, Faculty Glyphic, Happy Monkey, Iansui e Kalam.
- `app.css` define Faculty Glyphic como família principal e importa `components.css`; o `index.html` carrega Bulma, Font Awesome, fontes e `app.css`, permitindo personalização sem editar o arquivo distribuído do Bulma.
- `EstadoTema` e `PreferenciaTema`, em `Infraestrutura/`, centralizam a preferência Sistema/Claro/Escuro, persistida em `localStorage` na chave `rememore.tema.v1`. Sistema acompanha `prefers-color-scheme`; a preferência não é vinculada à conta.

## CMP-002 validado no `/lab`

- `ConfirmacaoNovaChave` — `src/Rememore.Client/Componentes/ConfirmacaoNovaChave.razor`: candidata do CMP-002 — Chave de redefinição. Recebe `Chave`, exibe `input type="text"` somente leitura e selecionável, e um botão com ícone Font Awesome `copy`. Usa `field`, `label`, `control has-icons-right`, `input` e `button`/`icon is-right` do Bulma. O clipboard é acionado pelo componente via `wwwroot/js/chaveClipboard.js`; `AoCopiar` reporta `true` apenas após sucesso da API e `false` para indisponibilidade/falha. Para demonstrar componentes reutilizáveis, o Lab deve renderizar o componente e dependências mínimas de teste, sem reproduzir a página que o consumirá. CMP-001 e CMP-002 compartilham a classe visual `icone-controle-interativo` em `components.css`, importado por `app.css`; estilos realmente compartilhados devem ser extraídos para essa folha, preservando escopo e especificidade necessários.

## CMP-003 concluído no `/lab`

- `SeletorData.razor` usa campo nativo `input type="date"` com classes Bulma `field`, `label`, `control has-icons-right` e `input`. Recebe somente `ValorInicial` e aplica internamente limite máximo igual a hoje no calendário local do navegador, calculado por `hojeLocal()` em `wwwroot/js/calendarioCaptura.js` (com fallback para `DateTime.Now` local); não recebe limite mínimo/máximo do chamador e não impõe limite retroativo. Emite `AoMudarValor` com a data somente quando completa, existente e não futura; em estados vazios, incompletos ou futuros, emite `null`. O estado inválido é refletido em `aria-invalid` e `seletor-data__entrada--texto-provisorio`, que aplica `--bulma-input-placeholder-color`; `:invalid` nativo também permanece coberto. O botão `is-ghost icon is-right` usa `icone-controle-interativo` de `components.css` e exibe Font Awesome `calendar`; um listener JavaScript síncrono chama `showPicker()` no clique para preservar a ativação do navegador e usa foco no campo como fallback, sendo removido ao descartar o componente. O indicador WebKit `::-webkit-calendar-picker-indicator` fica com `display: none` quando há ícone próprio; `opacity: 0` só o tornava invisível e ainda permitia que ele recebesse cliques. Esse comportamento segue o padrão pontual encontrado em `Stack1/assets/estilos.css`. Não há modos de mês/ano ou somente ano. A documentação oficial do Bulma não enumera `date` entre os tipos documentados, mas o CSS distribuído usa o seletor genérico `.input`.
- `DemonstracaoSeletorData` mantém uma única instância isolada e mostra o valor inicial recebido e a data válida emitida (ou ausência de data), com cenários vazio/incompleto, data inicial, hoje, passada e futura, além de limpar e editar. A instância separada de Capturar foi removida a pedido do operador para manter o Lab simples; ela havia sido testada antes da remoção. O navegador pode sanitizar entrada parcial do tipo date como valor vazio. Em viewport de 375 px, o `<select>` de cenário produzia overflow horizontal por seu box model intrínseco; `DemonstracaoSeletorData.razor.css` define `box-sizing: border-box` no select Bulma e a medição posterior ficou sem overflow. No navegador de teste `showPicker` não existia, portanto a abertura do popup nativo não pôde ser confirmada; o foco no campo após acionar o ícone com mouse e teclado foi confirmado pelo listener síncrono. Build do cliente em 17/10/2026 passou com 0 avisos/erros antes da última simplificação do contrato; as simplificações finais do contrato não foram retestadas pelo programador. O operador declarou o CMP-003 concluído após validação visual e funcional no Lab. `SeletorData_old.razor` e seu CSS preservam a versão anterior usada pela seleção real de Capturar; `SelecaoCapturar.razor` teve apenas o nome da tag trocado, sem alteração intencional do fluxo da página. As definições locais 04.06–04.08 não foram encontradas.
- Aprendizado reutilizável do CMP-003: partir das estruturas e classes do Bulma; manter no CSS isolado apenas ajustes ligados a necessidades visuais observadas (neste caso, cor inválida e remoção do indicador nativo duplicado); concentrar no componente a lógica reutilizável para evitar que cada chamador a replique. Não criar classes de layout e estados customizados antes de haver necessidade concreta.
