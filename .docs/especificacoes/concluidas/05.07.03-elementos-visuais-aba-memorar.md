# 05.07.03 — Elementos visuais para a aba Memorar

## Objetivo

Preparar no `/Lab` os elementos visuais necessários à futura composição da aba Memorar, validando cada elemento em uma fase própria e, ao final, sua combinação numa demonstração simples.

Esta unidade trata somente da construção e validação visual dos elementos no laboratório. A integração na página de captura será uma unidade posterior.

## Contexto

A primeira aba da captura, antes chamada “Registrar e organizar”, chama-se “Memorar”. A referência histórica para seu fluxo está em 05.07 e nas alterações aprovadas em 05.10.

A Stack2 já demonstra os elementos ELM-01 a ELM-09 e os componentes reutilizáveis pertinentes. Esta unidade não cria nem revisa componentes CMP.

## Limite da unidade

O trabalho inclui:

- uma variação tipográfica para a linha da data;
- um elemento de abas com três rótulos;
- uma variação multilinha do campo de texto;
- uma variação combinada do botão com dois botões, ambos com ícone;
- o uso do ELM-07 para demonstrar a dica de atalhos;
- uma composição demonstrativa desses elementos no `/Lab`.

A demonstração serve para avaliar a apresentação e o encaixe visual. Ela não implementa a navegação entre abas, a inclusão funcional de memórias, atalhos, persistência, edição ou integração com a página real.

Não criar novos componentes Razor, serviços, contratos funcionais ou comportamentos de página.

## Fases de construção

### Fase 1 — Linha da data

Criar no `/Lab` uma amostra de linha de data com semântica apropriada para uma data (`time`). Sua aparência deve se aproximar da hierarquia tipográfica de título e parágrafo já usada no produto, com tamanho ligeiramente maior que o parágrafo.

A amostra é uma variação dos padrões tipográficos existentes, sem novo código ELM. Nesta fase, avaliar somente a apresentação da linha e sua relação com os demais elementos.

### Fase 2 — Abas

Demonstrar um elemento de abas com três rótulos:

- Memorar;
- Categorizar;
- Revisar.

O elemento define a apresentação visual das abas e distingue a aba selecionada das demais. Essa demonstração é estática; não implementa navegação nem estado funcional entre painéis.

Registrar o padrão como **ELM-10 — Abas**, seguindo a numeração estável do catálogo. Antes de escrever a marcação, consultar a documentação oficial do Bulma para o padrão de abas e sua estrutura.

### Fase 3 — Campo multilinha

Ampliar a demonstração do ELM-05 para incluir um campo de texto multilinha, ao lado da variante de uma linha já existente.

Usar o elemento e as classes documentados do Bulma. Esta fase define a apresentação do campo multilinha; não implementa gravação, atalhos ou proteção de rascunho.

### Fase 4 — Botões combinados

Ampliar a demonstração do ELM-06 com um grupo de dois botões combinados, ambos com ícone:

- Incluir memória;
- Cancelar inclusão.

O grupo demonstra a relação visual entre uma ação de confirmação e uma de cancelamento. Os botões são apenas exemplos visuais e não executam ações. Consultar a documentação oficial do Bulma para a estrutura de botões agrupados.

### Fase 5 — Dica de atalhos

Reutilizar o ELM-07 — Orientação Informativa para apresentar uma dica de atalhos. Não criar outro elemento para esse conteúdo. Esta fase verifica apenas sua apresentação no contexto da composição.

### Fase 6 — Composição demonstrativa

Após a validação individual das fases anteriores, montar no `/Lab` uma demonstração simples que combine a linha da data, as três abas, o campo multilinha, o grupo de botões e a orientação.

A composição não é um novo componente nem uma implementação da página de captura. Seu propósito é verificar hierarquia, alinhamento e continuidade visual entre os elementos aprovados.

## Diretrizes de implementação

Construir cada fase progressivamente: primeiro a estrutura semântica com as classes e a marcação documentadas do Bulma; depois os ajustes visuais necessários. CSS autoral deve permanecer limpo, localizado e reutilizável, sem modificar os arquivos distribuídos do Bulma.

Os elementos aprovados devem usar os estilos reais compartilhados do produto. O demonstrador do catálogo pode organizar e identificar as amostras, mas seus estilos exclusivos não devem virar estilos de produção.

Cada fase deve ser apresentada ao operador para avaliação antes do avanço à fase seguinte. A composição final também deve ser avaliada no `/Lab`; a validação dos elementos isolados não substitui a verificação conjunta.

## Critérios de conclusão

A unidade estará concluída quando:

- a linha da data estiver demonstrada como variação tipográfica, sem novo ELM;
- o ELM-10 — Abas apresentar as três etapas e diferenciar visualmente a selecionada;
- o ELM-05 demonstrar as variantes de uma linha e multilinha;
- o ELM-06 demonstrar o par combinado de botões com ícones;
- o ELM-07 for usado para a dica de atalhos;
- os elementos estiverem reunidos numa composição demonstrativa no `/Lab`;
- cada fase e a composição final tiverem sido avaliadas pelo operador;
- a validação técnica da unidade tiver sido registrada, sem confundir essa validação com o aceite visual do operador.

## Fora do escopo

Não implementar nesta unidade:

- integração à página real de captura;
- navegação funcional entre abas;
- inclusão, cancelamento ou edição funcional de memória;
- atalhos de teclado;
- persistência ou proteção de rascunhos;
- mudanças no contrato ou na aparência de componentes CMP existentes;
- novas regras de orientação progressiva.
